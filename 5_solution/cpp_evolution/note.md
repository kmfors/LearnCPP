# C++ 知识点演进整理

以知识点为组织单位，以「C++23 主线下的完整用法」为主体，版本演进作为补充。
每个知识点自包含文档与可编译代码，通过 `./build.sh` 一键验证。
**最低标准为 C++11，不涉及 C++98。**

---

## 整理原则

1. **知识点为主体**：每个知识点一个文件夹，独立自包含。
2. **C++23 为核心**：以 C++23 为主线，讲清现在怎么写。
3. **最低标准 C++11**：所有对比从 C++11 起，不涉及 C++98。
4. **版本演进作补充**：只在有版本差异时展开，无差异则只标版本号。
5. **代码可编译**：每个知识点附带可运行代码，文档与代码同源维护。
6. **主次分明**：六个梯队深度整理，补充特性用速查表兜底，不平均用力。

---

## 主线标准选择

- **主线**：C++23
- **最低标准**：C++11
- **原因**：
  - C++23 包含了对 C++20 的大量 DR（缺陷报告）修复，是 C++20 的完善版本
  - 补充了 `std::expected`、`std::mdspan`、`std::flat_map` 等关键库设施
  - GCC 13+ / Clang 16+ / MSVC 最新版对其核心特性支持良好
  - C++23 是当前最新的已发布标准，以此为主线可避免学完即过时
- **C++20 的关系**：C++23 建立在 C++20 之上，整理 C++20 特性（concepts、ranges 等）时
  会同时覆盖 C++23 的相关增强，不需要单独先学 C++20 再学 C++23。
- **旧标准**：C++11/14/17/20 仅在「写法对比」和「版本差异」中出现，不作为主线。

> **编译器建议**：使用 GCC 13+ / Clang 16+ / MSVC 2022 17.5+ 编译。
> 部分 C++23 库特性（如 `flat_map`、`stacktrace`）需要更高版本，整理时以实际编译器支持为准。

> **学习建议**：C++23 是整理主线，但面试和实际项目可能仍以 C++11/14/17 为主。
> 整理时注意标注每个特性的「引入版本」，以便快速定位。

## 目录结构规范

每个知识点文件夹统一采用以下结构：

```
NN_knowledge_name/
├── README.md                 ← 文档主体
├── demo_cpp11.cpp            ← C++11 写法（有版本差异时）
├── demo_cpp14.cpp            ← C++14 写法（有版本差异时）
├── demo_cpp17.cpp            ← C++17 写法（有版本差异时）
├── demo_cpp20.cpp            ← C++20 写法（有版本差异时）
├── demo_cpp23.cpp            ← C++23 写法（主线）
├── demo_*.cpp                ← 按子主题拆分的演示代码（与版本无关时）
├── pitfalls_syntax.cpp       ← 编译期坑
├── pitfalls_runtime.cpp      ← 运行期坑
├── pitfalls_version.cpp      ← 版本差异坑（固定多标准编译）
└── build.sh                  ← 一键编译运行
```

**说明**：
- `demo_cppNN.cpp` 按版本拆分，**只保留该知识点在不同版本下写法确实不同的文件**。如果某版本无差异，不建该文件。
- `demo_*.cpp`（不含版本号）用于与版本无关的子主题演示，如 `demo_decltype.cpp`。
- 三个 `pitfalls_*` 文件按坑的性质分类，无内容时删除。
- `build.sh` 统一命名，主线用 `-std=c++23`。

## 使用方法

1. **查看顺序**：从第一梯队开始，按序号推进，或按兴趣跳跃。
2. **整理新知识点**：
   - 在根目录建 `NN_knowledge_name/` 文件夹
   - 按「目录结构规范」创建文件
   - 按「README 结构模板」撰写文档
   - 跑通 `build.sh` 后更新本文件的「状态」列
3. **验证已有知识点**：进入对应文件夹，执行 `./build.sh`。
4. **回顾版本演进**：查看各知识点 README 的「版本演进」章节。
5. **查补充特性**：在本文件「补充特性速查表」中按版本查找。
6. **标注 C++23 特性**：整理时如涉及 C++23 独有内容，在 README 标题或备注中用 `[C++23]` 标注。

## 维护约定

- **一个知识点一个文件夹**，不合并不同知识点。
- **文档与代码同步**：改代码时同步更新 README 中的片段。
- **无内容章节删除**：不为了结构完整写空话。
- **版本信息标注清楚**：每个特性标注引入版本，有行为变化时注明分界版本。
- **坑按性质分类**：编译期、运行期、版本差异分开，不混在一个文件。
- **等级可调整**：整理中发现某个 ★★ 经常踩坑，升级为 ★★★ 并补进梯队。
- **速查表按版本组织**：查的时候通常是「C++XX 有什么」，而非「某特性属于哪个等级」。
- **C++20/23 合并整理**：C++23 是 C++20 的完善版，整理 C++20 特性时同步标注 C++23 的 DR 修复和增强，不单独拆开。
- **编译器验证**：主线代码用 `-std=c++23` 编译，版本对比固定用 `c++11 c++14 c++17 c++20 c++23`。
- **标注编译器版本要求**：对支持较晚的特性（如 flat_map、mdspan），在备注中注明最低编译器版本。
- **最低标准 C++11**：不涉及 C++98，所有对比从 C++11 起。
